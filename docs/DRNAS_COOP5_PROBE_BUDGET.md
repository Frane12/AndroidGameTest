# DRNAS COOP5 — fixed 25 ms versus dynamic BCP probe control

**Status:** isolated experimental branch. Main, frozen X5 binaries, trained memory,
and reference benchmark datasets are untouched. No automatic promotion.

## User requirement and two real executables

The same frozen X5-derived C++ CDCL source is compiled twice with one compile-time
policy switch. This yields TWO distinct executable artifacts:

- \`build/drnas-coop5-fixed\` — fixed two-probe sampling, total soft wall budget
  **25 ms per solve**, each branch propagates at most **320 inspected clauses/
  binary edges**, with at least **24 decisions** between probe pairs.
- \`build/drnas-coop5-dynamic\` — dynamic two-probe sampling, initial **96
  inspections / 64 decisions**, expanding to **320 / 900 inspections** and
  shorter decision intervals after sufficiently strong observed proxy gains.
  After three weak proxy passes it reduces depth and increases the interval,
  bounded by 256 decisions. Its total soft wall budget is **min(25 ms,
  max(1 ms, 0.005 × solve-time-in-seconds × 1000 ms))** — thus 25 ms at
  a 5-second cap, 5 ms at 1-second cap.

"25 ms" means CUMULATIVE time spent in BCP probe pairs for that formula, **not**
one new sample every 25 ms. A pair can slightly overrun the soft wall budget;
a strict per-pair limit on inspected operations also applies.

## Branch choice protocol

1. Preserve plain CDCL, proof-certified local affine learning, watch lists and
   1-UIP. Do nothing for fewer than 64 native conflicts.
2. Only when algebra's proposed variable differs from normal CDCL's
   highest-ranked VSIDS variable, consider a probe pair.
3. Simulate (under identical stable pre-decision CDCL state) one temporary BCP
   path with the frozen VSIDS variable's current phase and one with the algebra
   variable's existing phase. Each probe rolls back to the original state.
4. Compare unresolved long-clause sample distance and BCP implied variables.
   A sufficiently large **proxy** advantage can change the variable only.
   Never infer SAT/UNSAT or insert a clause from any speculative branch.
5. SHADOW does the same work and computes the same suggestions, but NEVER
   changes which variable CDCL chooses. Use it to isolate sampling overhead.
6. ON changes the variable only if the proxy threshold clears. Other hints
   and incomplete evidence fall back to ordinary CDCL.
7. DYNAMIC additionally adjusts probe depth and spacing from proxy hits and
   actual immediate propagation feedback. It does not change the proof
   machinery or trust a proxy as a correctness certificate.

## Safety and limits

Every certified SAT is independently checked against the entire ORIGINAL CNF,
and each UNSAT must pass DRAT-trim against ORIGINAL CNF. Independent RUP proof
audit is run on exhaustive 3-variable truth tables and random small formulas.
All solvers use one logical CPU, serial attempts and paired per-case randomized
arm order. The two probe builds have separately frozen SHA-256 identities.

A safe probe can still lead to a very bad SAT search path. More BCP implications
or fewer locally long clauses are *heuristics only*. We therefore distinguish
\`ALGEBRA\`, \`DIRECT_ON\`, \`FIXED_SHADOW\`, \`FIXED_ON\`,
\`DYNAMIC_SHADOW\`, \`DYNAMIC_ON\`, and independently frozen X5.

Benchmarks use retrospective original SAT2024 REAL36 CNFs eligible under the
existing 4096-variable/12000-clause algebra limit, plus a separate 21-source
seven-family stress-synthetic cohort. Performance improvements cannot be
claimed for unseen SAT2024 formulas from these sets. No solver is promoted
unless a future source-disjoint blind holdout supports a verified PAR2 gain.

## Interpret time and instructions

- \`probe_wall_ms / attempted_pairs\` measures ONLY the BCP pair within each
  program. Process launch, algebra preparation, watcher changes, and the
  subsequent differing search path can add unmeasured effects.
- \`SHADOW - ALGEBRA\` approximates total probing overhead with no branch
  overrides (same solver source, some normal noise).
- \`ON - SHADOW\` tests if accepting the proposed branch was worth its cost;
  not a formally identical-state paired counterfactual.
- No difference smaller than natural execution noise should be called a win.

## Usage

\`\`\`sh
python3 research/drnas_coop5/build.py
build/drnas-coop5-fixed path/to/input.cnf --mode core --time 5 --stats --proof tmp.drat --coop4 on --coop5 shadow
build/drnas-coop5-fixed path/to/input.cnf --mode core --time 5 --stats --proof tmp.drat --coop4 on --coop5 on
build/drnas-coop5-dynamic path/to/input.cnf --mode core --time 5 --stats --proof tmp.drat --coop4 on --coop5 on
\`\`\`

All evidence generated by this version is development evidence, not blind.
