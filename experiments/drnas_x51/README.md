# X5.1 bounded minimization experiment

Frozen baseline: X5 source/binaries from 9f0c37c and run 43368689724. The candidate is a separate source file; default search is unchanged except observational counters. No persistent/global memory is read or updated by this experiment.

The X5 budget charged recursive calls (4000/clause) but not every reason literal. X5.1 bounded mode charges calls and reason edges, stopping at 256 units/clause. Exhaustion retains the literal; the existing independent DRAT checker remains mandatory. The optional adaptive mode initially uses 256 units, evaluates deterministic windows of 256 minimized clauses, reduces to 64 for low observed yield (<2% removed and >64 work/removed), probes 256 every 16th call, and restores 256 when yield exceeds 5% with <48 work/removed. These are fixed experimental heuristics, not proven performance improvements. No category labels, hashes, expected answers, future results or wall timers enter the policy.

Six arms: frozen X5, frozen X5 without minimization, X5.1 passive telemetry, X5.1 bounded, X5.1 adaptive, frozen Kissat. All X5.1 arms have identical instrumentation. Passive comparison quantifies observer/compiler overhead. The passive control must preserve conflict/decision/propagation/restart counts on completed independent truth-table cases.

Telemetry records cumulative propagation/analysis/minimization time, clause lengths before/after minimization, reason traversal work, budget exhaustion, policy switches, restart counts, and live learned clauses/literals. Analysis time includes minimization; do not add them. Timeout snapshots are partial and may be absent if the first snapshot was not reached. Logs are retained through process termination. Linux pidfd waits avoid Python timeout polling quantization. All arms use the same runner and a shared 5-second solve-plus-verification deadline. Unverified/late outcomes receive PAR2=10.

The committed protocol locks 45 diagnostic and 45 holdout sources: 15 each of cardinality, XOR and uniform random 4-SAT. Both sets share generation templates; this is instance holdout, not industrial or family-level generalization. Source offsets are distinct from MIX96, DIVERSE72, and implementation smoke inputs. All sources are generated without screening. Each split runs 3 repetitions, 6 arms, 3 serial single-CPU shards (810 trials/split). Holdout runs automatically after successful diagnostic completion with the same binary, parameters and source manifest. There is no tuning between splits and no automatic promotion.

Candidate qualification on holdout requires >=10% lower verified PAR2 than both native controls, positive source-bootstrap lower confidence bound, and no per-category solved-count regression. Multiple experimental candidates and shared templates limit interpretation; any promising result requires new validation and original industrial CNFs.

Local initial validation: 1128 candidate runs, 676 independent UNSAT proof checks, 264 completed-case passive search equivalence checks, malformed-DIMACS rejection, and deliberately invalid proof rejection. Separate smoke inputs exercise budget exhaustion, adaptive state changes and timeout telemetry. CI repeats correctness before benchmarks.
